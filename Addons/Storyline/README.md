# Storyline System Documentation

## Overview
The storyline system manages dialogue and character interactions in the game. It consists of several components that work together to display text, play character sounds, and manage storyline progression.

## System Components

### Core Files
- `storyline_manager.gd` - Main manager that handles storyline events and tracks played events
- `storyline_controller.gd` - Canvas layer that handles text rendering and audio playback
- `storyline_canvas.tscn` - UI scene for displaying storyline text and character portraits
- `storyline.json` - JSON file containing all storyline events and dialogue
- `storyline_test.gd` - Testing interface for storyline events

### Storyteller System
- `Storytellers/` - Directory containing all character storyteller resources
- `puhe/` - Directory containing all character voice/speech sound files
- `storyteller.gd` - Script that defines storyteller resource structure

## Adding a New Storyteller

When adding a new storyteller character to the system, follow these steps:

### 1. Create Sound Files
1. **Record voice lines** for the new character (5 different variations recommended)
2. **Save as WAV files** with descriptive names (e.g., `newcharacter1.wav`, `newcharacter2.wav`, etc.)
3. **Place files** in `addons/Storyline/puhe/` directory
4. **Import files** will be automatically generated by Godot

### 2. Create Character Portrait Scene
1. **Create new scene** in `addons/Storyline/Storytellers/` directory (e.g., `newcharacter.tscn`)
2. **Add AnimatedSprite2D** or similar node for character portrait
3. **Set up animations** (at minimum, create a "default" animation)
4. **Configure sprite frames** and animation settings
5. **Save the scene**

### 3. Create Storyteller Resource
1. **Create new resource** in `addons/Storyline/Storytellers/` directory (e.g., `newcharacter.tres`)
2. **Set script** to `res://Addons/Storyline/storyteller.gd`
3. **Configure properties:**
   - `id`: Unique identifier (e.g., "newcharacter")
   - `teller_name`: Display name (e.g., "New Character")
   - `sounds`: Array of AudioStreamWAV resources (drag sound files from puhe folder)
   - `scene`: PackedScene resource (drag the .tscn file created in step 2)

### 4. Update Storyline Canvas
1. **Open** `storyline_canvas.tscn` in the editor
2. **Select** the `StorylineCanvas` node
3. **In the Inspector**, find the **Storytellers** array property
4. **Add new element** and drag the new storyteller `.tres` into it
5. **Save the scene**

### 5. Add to Storyline JSON
1. **Open** `storyline.json`
2. **Add new events** that use the new character
3. **Use the character's ID** in the "actor" field of speeches
4. **Example:**
```json
{
  "event": {
    "name": "NewCharacterIntro",
    "speeches": [
      {
        "speech": {
          "actor": "newcharacter",
          "text": [
			"Hello! I'm the new character in this story.",
			"I have important things to tell you."
          ]
        }
      }
    ]
  }
}
```

### 6. Test the New Storyteller
1. **Open** `storyline_test.tscn` in the editor
2. **Run the scene** to test the new storyteller
3. **Verify** that:
   - Character portrait appears correctly
   - Voice sounds play during dialogue
   - Text displays properly
   - Character animations work

## Storyteller Resource Properties

### Required Properties
- **`id`** (String): Unique identifier used in storyline.json
- **`teller_name`** (String): Display name for the character
- **`sounds`** (Array[AudioStreamWAV]): Array of voice sound files
- **`scene`** (PackedScene): Scene containing character portrait

### Sound File Guidelines
- **Format**: WAV files recommended for voice
- **Quantity**: 3-5 variations per character
- **Naming**: Use descriptive names (e.g., `character1.wav`, `character2.wav`)
- **Length**: Keep individual sounds short (1-3 seconds)
- **Quality**: Use clear, consistent audio levels

### Portrait Scene Guidelines
- **Node Type**: Use AnimatedSprite2D for animated portraits
- **Animations**: Create at least a "default" animation
- **Size**: Keep portraits reasonably sized (not too large/small)
- **Positioning**: Portrait will be positioned automatically by the system
- **Performance**: Keep animations simple for good performance

## Fallback System

The storyline system includes a robust fallback system to prevent crashes when assets are missing:

### Automatic Fallbacks
- **Missing Storyteller**: Uses placeholder storyteller with "?" indicator
- **Missing Portrait Scene**: Creates red-tinted fallback visual with "?" label
- **Missing Sound Files**: Uses placeholder silent audio files
- **Invalid Sound References**: Automatically loads placeholder sounds

### Fallback Assets
- **Placeholder Sounds**: `addons/Storyline/puhe/placeholder1.wav`, `placeholder2.wav`, `placeholder3.wav` (used by `placeholder.tres` / `"actor": "narrator"`)
- **Placeholder Portrait**: `addons/Storyline/Storytellers/placeholder_narrator.tscn`
- **Placeholder Resource**: `addons/Storyline/Storytellers/placeholder.tres` (also the only `"actor": "narrator"` entry in `storyline_canvas.tscn`; unknown actors use the same resource via preload)

### Debug Information
The system prints warnings to the console when fallbacks are used:
- `"Warning: Storyteller 'X' not found, using placeholder"`
- `"Warning: No scene available for storyteller 'X', creating fallback"`
- `"Warning: Sound file missing for storyteller 'X', using placeholder"`

## Visual Feedback System

The storyline test interface includes a color-coded system to track played storylines:

### Button Color System
- **White/Default**: Storyline has not been played yet
- **Gray**: Storyline has already been played
- **Text Indicator**: Played storylines show "(played)" in the button text

### Reset Functionality
- **Reset Button**: Clears all played storylines and restores original button colors
- **Visual Reset**: All buttons return to white color and remove "(played)" text
- **Functional Reset**: Storylines can be played again after reset

### Usage
1. **Play storylines** by clicking buttons - they turn gray when played
2. **Track progress** visually - gray buttons indicate completed storylines
3. **Reset system** using the "Reset Storylines" button to replay everything
4. **Test thoroughly** by playing different combinations and resetting

## Troubleshooting

### Common Issues
1. **No sound playing**: Check that sound files are properly imported and referenced
2. **Portrait not showing**: Verify the scene is properly set in the storyteller resource
3. **Character not appearing**: Check that the storyteller is added to the storyline manager
4. **JSON errors**: Validate JSON syntax and ensure actor IDs match storyteller IDs
5. **Fallback indicators**: Red "?" indicators mean missing assets - check console for warnings

### Testing Checklist
- [ ] Sound files play correctly
- [ ] Character portrait displays
- [ ] Animations work properly
- [ ] Text displays correctly
- [ ] Character appears in storyline test interface
- [ ] No console errors or warnings
- [ ] Button colors change when storylines are played
- [ ] Reset button restores original button colors

## Best Practices

### Sound Design
- Record multiple variations for natural speech patterns
- Use consistent audio levels across all sound files
- Test sounds in the actual game context
- Consider using different emotional tones for variety

### Character Design
- Keep portrait animations simple and clear
- Ensure characters are visually distinct
- Use consistent art style across all storytellers
- Test portraits at different screen sizes

### Storyline Writing
- Use clear, descriptive event names
- Keep dialogue concise and engaging
- Test storylines with the test interface
- Consider branching dialogue for complex interactions

## Maintenance

### Regular Tasks
- **Backup** storyline.json before major changes
- **Test** all storytellers after system updates
- **Validate** JSON syntax when adding new events
- **Check** sound file references after moving files
- **Update** documentation when adding new features

### Version Control
- **Commit** storyteller resources and sound files
- **Track** changes to storyline.json
- **Document** major storyline additions
- **Test** changes before committing
